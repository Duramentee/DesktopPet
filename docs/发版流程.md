# 发版流程

> 本流程只描述发版动作本身。编译环境与验收步骤见 `docs/构建清单.md`，功能范围见 `docs/需求说明.md`。
> 发版以 Windows 产物为主：macOS 与 Linux 尚未实机验证，产物补齐之前不挂到 Release 上。

## 一、版本号只改这三处

| 文件 | 字段 | 说明 |
|---|---|---|
| `package.json` | `version` | 前端与整个仓库的版本号；同时会更新 `package-lock.json` 里记录的两处 |
| `src-tauri/tauri.conf.json` | `version` | 决定安装包文件名与 Windows 文件属性里的版本，运行时的 `getVersion()` 也读这里 |
| `src-tauri/Cargo.toml` | `version` | Rust crate 的版本号，`Cargo.lock` 会在下一次构建时同步 |

三处必须一致，否则安装包文件名、日志里的版本号与仓库标签会对不上。改完执行一次构建，`src-tauri/Cargo.lock` 会自动更新。

## 二、更新更新日志

`CHANGELOG.md` 按「新增 / 变更 / 修复 / 已知限制 / 验证数据」五节记录当前版本，未完成的事项放进「未发布」一节。验证数据里的测试数量、产物体积、待机开销三项必须取自本次构建的实测值，不能沿用上一版。

## 三、构建并记录产物

```powershell
npm test
npm run typecheck
npm run tauri build
Get-ChildItem src-tauri\target\release\bundle -Recurse -Include *.msi,*.exe |
  Select-Object Name, @{Name='兆字节';Expression={[math]::Round($_.Length/1MB,2)}}
Get-FileHash src-tauri\target\release\bundle\nsis\*.exe, src-tauri\target\release\bundle\msi\*.msi -Algorithm SHA256 |
  Select-Object Hash, Path
```

校验和要写进 Release 说明，下载方可以据此核对文件是否完整。

## 四、提交并打标签

标签名与版本号一致，前缀 `v`，用附注标签把产物信息写进标签本身。

```powershell
git add -A
git commit -m "release: 0.2.0"
git tag -a v0.2.0 -m "桌面宠物 0.2.0：首个公开发布版本"
git push
git push origin v0.2.0
```

## 五、创建 GitHub Release

仓库没有配置自动发布的工作流，Release 需要手工创建。两种方式任选其一。

使用 GitHub CLI（需先执行 `gh auth login`）：

```powershell
gh release create v0.2.0 `
  src-tauri\target\release\bundle\nsis\desktop-pet_0.2.0_x64-setup.exe `
  src-tauri\target\release\bundle\msi\desktop-pet_0.2.0_x64_en-US.msi `
  --title "桌面宠物 0.2.0" `
  --notes-file CHANGELOG.md
```

使用网页：打开仓库的 Releases 页面，选择「Draft a new release」，标签选择刚推送的 `v0.2.0`，标题填「桌面宠物 0.2.0」，正文粘贴 `CHANGELOG.md` 里 0.2.0 那一节，上传两个安装包，发布。

## 六、发布后核对

| 核对项 | 期望结果 |
|---|---|
| Release 附件 | 安装程序与安装包两个文件都在，体积与本地一致 |
| 校验和 | 下载后重新计算 SHA256，与 Release 说明里的一致 |
| 干净环境安装 | 在一台没有装过本程序的机器上安装并启动，宠物出现且能拖动 |
| 安全提示 | 首次运行出现 SmartScreen 蓝色提示，按文档说明可以选择「仍要运行」 |
| 版本号 | 日志第一行显示本次版本号，与标签一致 |
