## 2026-10-20 第一轮：需求梳理、技术选型与第一迭代骨架

### 一、需求确认过程

本轮开始时工作区为空目录，没有既有代码。通过三轮问答确定了需求基线，结论如下。

| 需求项 | 最终结论 | 提出方 | 对设计的影响 |
|---|---|---|---|
| 目标平台 | Windows、Linux、macOS 三个平台都适配，优先级为 Windows 高于 macOS，macOS 高于 Linux | 用户 | 平台层必须以接口抽象，每项系统能力在三个平台上分别实现 |
| 宠物外观 | 需要动画，并且外观必须与逻辑解耦、可以更换 | 用户 | 引入皮肤包概念，逻辑层只引用动画名称 idle 与 drag |
| 养成系统 | 第一迭代不包含养成数值与存档演化 | 用户 | 领域层只包含状态机、动画播放器、位置约束、坐标换算、清单校验、配置处理 |
| 交互深度 | 第一迭代只包含拖拽与右键菜单 | 用户 | 状态机只有待机与拖拽中两个状态 |
| 维护方式 | 由人工智能负责维护，人类不参与日常代码维护 | 用户 | 可读性与人工接手成本不列入目标，改用体积、占用、分发、一致性等可量化目标 |
| 非功能目标 | 打包体积小、运行占用低、分发容易、多平台表现一致、动画流畅、缺陷少 | 用户 | 直接否决了 Electron 方案，改用 Tauri |
| 项目定位 | 自用为主，最多在 GitHub 开源供他人使用，无商业需求 | 用户 | 不申请代码签名证书、不实现自动更新、不实现使用统计、采用 MIT 许可证 |
| 开发环境 | WSL2 加 WSLg，真机验收在 Windows 侧进行 | 用户 | WSL 只承担测试与构建，不承担运行验收 |

### 二、技术选型的两次调整

第一次选型为 Electron 加 TypeScript，理由是三个平台都内嵌 Chromium，渲染结果完全一致。该结论在用户补充「打包体积要小、运行占用要低」之后被推翻：Electron 的安装包在八十到一百二十兆字节量级，待机内存在一百兆字节以上，无法通过工程手段削减。

第二次选型为 Tauri 第二版 加 TypeScript 加 Canvas。判断依据有四条：第一，Windows 安装包可以控制在十五兆字节以内，比 Electron 低一个数量级；第二，WebView2 已随 Windows 十 1803 及以上版本与 Windows 十一预装，分发时不需要引导用户安装运行时；第三，窗口置顶、系统托盘、配置存储三项能力都有官方插件，平台特定代码量小；第四，Canvas 逐帧绘制不经过布局引擎、字体渲染与 CSS 合成，是渲染引擎差异最小的绘制方式。

被否决的另外两个方案是 Wails 第二版 与 Rust 原生自绘。前者在四项指标上与 Tauri 接近但没有明显优势；后者在体积、内存、渲染一致性三项上更强，但需要自行实现三个平台的分层窗口、按像素判定鼠标命中与高清屏缩放，第一迭代出现缺陷的范围明显更大，与「缺陷尽量少」这一目标冲突。

### 三、测试驱动开发的执行过程

第一步先建立工程配置与夹具，然后把需求文档第 9.2 节的十八条用例全部写成测试。第一次运行结果为六个测试文件全部失败，失败原因是被测模块尚不存在，这构成红色阶段。

第二步实现领域层六个模块，再次运行时有两条用例失败。复核后确认是实现正确、测试期望值写错：指针位于 (98, 186)、锚点位于 (100, 200)，两者差值为 (−2, −14)，指针移动到 (300, 400) 之后锚点应为 302 与 414，而测试写成了 298 与 386。修正测试期望值后全部通过，这构成绿色阶段。

第三步继续以同样的方式扩展：先写控制器的用例（十二条），再实现控制器；先写窗口后端与皮肤仓库的用例（九条），再实现对应适配；最后补充真实皮肤资源、运行环境识别与皮肤仓库的用例。

### 六、本轮遇到的问题与处理

| 问题 | 现象 | 处理方式 |
|---|---|---|
| 测试期望值算错 | 拖拽位移用例期望 (298, 386)，实现输出 (302, 414) | 复核几何关系后确认实现正确，修正测试中的算术 |
| 类型检查缺少 Node 类型 | `node:fs`、`node:path`、`process` 报找不到名称 | 安装 `@types/node` 并在 tsconfig 的 types 字段中声明 |
| 右键菜单回调类型不匹配 | 控制器返回 Promise 布尔值，菜单接口声明 Promise 空值 | 把菜单回调的返回类型放宽为 Promise 未知值或空值 |
| 皮肤索引测试的桩对象缺陷 | 桩函数用空值合并运算符处理索引缺省值，导致显式传入空值被替换成缺省值 | 改为先判断字段是否存在，再决定返回显式空值还是缺省值 |
| WSL 图形会话限制 | 透明、置顶、穿透、托盘在 WSLg 下均不可信 | 新增 runtime_info 命令与运行环境识别模块，启动时输出降级警告；把验收改到 Windows 侧 |
