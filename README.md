# 桌面宠物

一个运行在桌面最上层的宠物程序。宠物循环播放待机动画，用户可以按住宠物并拖动到屏幕上的任意位置，也可以通过右键菜单切换置顶状态、开关开机自启，并在皮肤管理窗口里挑选外观。宠物的外观由外部皮肤包决定，程序本身不包含任何硬编码的形象资源。

## 当前状态

第一迭代与第二迭代已完成：Windows 侧完成编译、运行、打包与七项手工验收，安装包约一点二兆字节，待机内存约三十兆字节。第二迭代补充了开机自启与显示器布局变化后的坐标修正，第三迭代补充了高清屏下的画布清晰度与缩放比例变化后的重新对齐，第四迭代补充了日志落盘与运行诊断，第五迭代把皮肤切换收进了独立的皮肤管理窗口，第六迭代加入了待机时的呼吸与张望，第七迭代让皮肤包支持热加载，第八迭代补上了单实例约束，第九迭代实现了透明像素的点击穿透，第十迭代把绘制频率压到每秒三十帧并用进程树口径复核了 CPU 占用。需求文档见 `docs/需求说明.md`。

## 运行要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| Node.js | 二十或更高版本 | 用于构建前端与运行单元测试 |
| Rust | 一点七七或更高版本 | 用于编译 Tauri 外壳 |
| Windows | Windows 十 1803 及以上，或者 Windows 十一 | 需要系统预装 WebView2 运行时，上述版本已默认包含 |
| macOS | 十一或更高版本 | 使用系统自带的 WebKit 渲染 |
| Linux | 需要 X11 会话与 WebKitGTK 四点一 | 在 Wayland 会话下窗口置顶与鼠标穿透可能失效 |

在 Debian 或 Ubuntu 上，编译 Tauri 外壳需要先安装下列系统软件包。

```bash
sudo apt update
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
```

## 开发与测试

| 目的 | 命令 | 说明 |
|---|---|---|
| 安装依赖 | `npm install` | 安装前端依赖与 Tauri 命令行工具 |
| 运行全部单元测试 | `npm test` | 在 Node 环境下运行，不创建任何窗口 |

## 排查问题

程序没有控制台，页面的警告、错误、未捕获异常与 Rust 侧的 panic 都会写进日志文件。右键菜单里的“打开日志目录”可以直接定位到该目录。

| 平台 | 日志位置 |
|---|---|
| Windows | `%LOCALAPPDATA%\io.github.desktoppet\logs\app.log` |
| macOS | `~/Library/Logs/io.github.desktoppet/app.log` |
| Linux | `~/.local/share/io.github.desktoppet/logs/app.log` |

日志按行记录，单文件超过五百一十二千字节后滚动为 `app.log.1`。绘制频率被限制在每秒三十帧，实际帧率低于二十四帧时会写一条警告，正常状态每十分钟留一条心跳；托盘的提示文字会显示当前帧率与常驻内存。

## 在 WSL 中开发

WSL2 的图形输出由 WSLg 提供，它通过远程桌面协议把 Linux 窗口转发到 Windows 桌面，因此不具备原生的窗口层级控制与托盘协议转发能力。在本项目中 WSL 只承担开发与自动化测试职责，不承担运行与验收职责。

| 用途 | 在 WSL 中是否可以完成 | 说明 |
|---|---|---|
| 单元测试、类型检查、前端构建 | 可以完整完成 | 这些步骤不创建窗口，与图形会话无关 |
| 生成皮肤与图标资源 | 可以完整完成 | 脚本只写文件，不依赖图形环境 |
| 启动宠物窗口并验收 | 不可以 | 透明背景、窗口置顶、鼠标穿透与系统托盘四项能力在 WSLg 下都会降级或者失效 |
| 编译并运行 Rust 外壳 | 可以编译，不能验收外观 | 编译需要先安装 WebKitGTK 等系统依赖，运行后的外观不可信 |

因此真机验收在 Windows 侧原生进行：把仓库放到 Windows 文件系统上的独立目录（例如 `C:\dev\DesktopPet`），在 Windows 中安装 Node.js 与 Rust（使用 MSVC 工具链），然后在那个目录执行 `npm install` 与 `npm run tauri dev`。两个副本之间用 Git 同步，不要共享 `node_modules`，因为 `vite`、`rollup` 与 `esbuild` 都会安装与平台绑定的原生二进制，Linux 版本与 Windows 版本不能混用。

## 皮肤包制作

皮肤包是 `assets/skins` 下的一个子目录，目录名即皮肤标识，目录内必须包含 `skin.json` 与一个 `images` 子目录。清单字段与校验规则见 `docs/需求说明.md` 第 5 节。新增皮肤之后需要把它登记到 `assets/skins/index.json` 的 `skins` 数组中，右键菜单的“皮肤管理…”窗口中才会列出这份皮肤。

运行中也可以用用户皮肤目录热加载，不需要重新打包：

| 平台 | 用户皮肤目录 |
|---|---|
| Windows | `%APPDATA%\io.github.desktoppet\skins` |
| macOS | `~/Library/Application Support/io.github.desktoppet/skins` |
| Linux | `~/.local/share/io.github.desktoppet/skins` |

在该目录下放一份与内置皮肤结构相同的子目录即可：同名标识会覆盖内置皮肤，新标识会追加到列表末尾，删掉子目录就恢复内置版本。程序每两秒检查一次目录内容，变化后会自动重新加载当前皮肤，皮肤管理窗口也会刷新列表与预览。

清单必须提供 `animations.idle` 与 `animations.drag` 两个动画，每个动画必须声明 `fps`、`loop` 与 `frames`，每个帧必须声明相对皮肤目录的 `file` 路径。可选字段有三项：清单中的 `hitbox` 用于缩小可点击区域，帧上的 `durationMs` 用于覆盖由帧率推算出的单帧时长，清单中的 `displayName` 用于在菜单中展示可读名称。

## 已知限制

| 平台 | 限制 | 原因与处理方式 |
|---|---|---|
| Linux 的 Wayland 会话 | 窗口置顶与鼠标穿透可能不生效 | Wayland 协议不允许应用自行决定窗口层级与输入区域，程序会记录一条警告并继续运行 |
| Linux | 需要系统提供 WebKitGTK 四点一，未安装的发行版无法启动 | 属于运行时依赖，需要用户自行安装 |
| WSL2 | 透明背景、窗口置顶、鼠标穿透与系统托盘都会降级或者失效 | WSLg 通过远程桌面协议转发窗口，不采纳窗口层级与输入区域请求，也不转发托盘协议；程序启动时会输出对应的警告日志 |
| macOS | 首次打开时会被系统阻止 | 程序未经过苹果公证，用户需要在系统设置的隐私与安全性页面手动放行 |
| Windows | 下载后首次运行会出现 SmartScreen 提示 | 程序未签名，用户需要点击「仍要运行」 |
| 全部平台 | 不支持自动更新 | 升级需要重新下载安装包，程序不发起任何网络请求 |
